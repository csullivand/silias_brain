# 2026-08-14

## SL-1576 Feature 2.1 [BE] — Row Fill Rules persistence
Rama `feat/SL-1576-persistencia-reglas-fill` · PR #1991. Sesión: [[Claude Sessions/silia/SL-1576-row-fill-rules/2026-08-14]]

### Qué se hizo
- BE completo para persistir reglas de coloreado condicional de filas, **per-usuario** (por vista, como filtros), espejo de FilterBarConfig: validador propio, model + GSI, GET/PUT, SAM (tabla/KMS/role/2 fns), tests.
- **Validador por-id** (no `validateAndResolveFilters` que resuelve por name) reusando `ALLOWED_OPERATORS` + shape checks + paleta cerrada.
- **Cascade-delete** al borrar tabla (se suma a KpiPrefs/UserViewConfig).
- **Paleta 6→10** (+orange,cyan,pink,brown) a pedido de diseño (vía Camila).
- Reviews: PR review + adversarial verify independiente, ambos PASS.
- Removí el doc FE del PR (se trackea aparte).

### Decisiones
- Per-user, no per-tabla — settled por arquitectura Data Views (4.3/5.1/7.1 keyed user_id+table_id), no era open question del 2.1.
- Paleta: opción A (lista cerrada de 10) en vez de aflojar la validación. Trade-off anotado: cada cambio de paleta = deploy de BE.
- 400+errorCode, updatedAt en segundos (alineado al resto de DynamicTables).

### Contexto
- Feature 4.3 (Kanban view config per user) es ticket aparte — solo lo revisé, no desarrollé. Reveló que la familia de config per-user cascadea al borrar tabla → gap que cerré para Row Fill.
