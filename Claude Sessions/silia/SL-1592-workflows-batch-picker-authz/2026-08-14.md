### Step 2: Frontend — where GET /v1/workflows?assistantId is called + is there account validation?
- **Callers:** `app/src/features/data-views/services/workflowsService.ts:56` (`getWorkflows`, used by `ButtonConfigModal`) and `app/src/features/assistants/services/flowService.ts:19` (`fetchProcessFlowCards`, via `useWorkflows`).

### Step 7: status filter follow-up (found by review)
- **Bug:** batch path (`findByAssistantIds`→`findByAssistantId`) had no `status` FilterExpression, unlike `queryByAssistantId`/`queryByAccountId`. So `?assistantIds=a,b&status=active` returned all statuses.
- **Fix:** in `findByCriteria`, after batch merge, `params.status ? results.filter(w => w.status === params.status) : results`. `findByAssistantIds` stays a pure by-ids query.

### Step 10: PRODUCTION CRASH — getter TypeError at Lambda load
- **Error:** `TypeError: Cannot set property getWorkflowsHandler of #<Object> which has only a getter` at `getWorkflowsHandlerMin.js` load.
- **Root cause:** I had added `export const getWorkflowsHandler` (ESM) to make it testable, while the file also does `exports.handler = middy(...)` (CJS). The `export` flips the module to webpack "harmony" → named export defined as a getter → collides with the CJS assignment at load.
- **Fix:** all-CommonJS. Declare handler as plain `const getWorkflowsHandler`; expose for tests via `exports.getWorkflowsHandlerImpl` (NOT `getWorkflowsHandler` — webpack's output `library` name equals the file basename, so a same-named export gets clobbered to an empty `{}` in the bundle). Test import: `import { getWorkflowsHandlerImpl as getWorkflowsHandler }`.
- **Verified by BUILDING the bundle:** `NODE_ENV=production npx webpack --env component=Workflows/application/GetWorkflows/getWorkflowsHandler.ts` then `require()` → `LOAD OK`, `handler` is a function, `getWorkflowsHandlerImpl` is a function. (`dist/` is gitignored — built in CI.)
- **Sibling `getAgentWorkflowReferencesHandler.ts` uses the SAME broken `export const` + `exports.handler` pattern** — same latent landmine, not a safe template.
