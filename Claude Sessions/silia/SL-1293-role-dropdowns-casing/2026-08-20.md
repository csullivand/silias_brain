## Trabajo (esta sesión)

### 1. Bug 'sulli' — resolución de rol case-sensitive
- FE manda nombres de rol en minúsculas; custom roles guardados as-typed → 'sulli' no encontraba 'Sulli' → 400 role_not_found.
- Fix: RoleModel.findByAccountAndName querea por accountId (hash) y matchea nombre case-insensitive (exact-preferred). resolveRoleId normaliza cache key + fallback a defaults. Beneficia create/update/clone/resolve.

### 2. Superadmin asigna cualquier rol (también a usuarios)
- isReservedOrgRole(role, callerRole?) → superadmin caller bypasa la denylist; el resto (incl. implementador) sigue bloqueado. Enhebrado en createOrgUser (POST), createOneOrgUser/batch, patchOrgUser (PATCH).
- Antes solo estaba el bypass en grants; faltaba la ruta de asignación de rol de usuario (el bug de Camila 'role superadmin cannot be assigned').

### 3. Endpoint reassign masivo
- POST /role/{id}/reassign {targetRoleId, deleteSource?}: mueve users(nombre)+grants(id), invalida cache, opcional soft-delete. Best-effort/idempotente. + build scripts en package.json (blocker que encontró PR review).

### 4. Case-insensitive en user.model (3 lookups)
- countByRole, listUserIdsByRole: drop del filtro #role, match in-memory case-insensitive (+ countByRole ahora pagina). Cubren delete guard e invalidación de cache.
- listByAccount: filtro de rol in-memory (la paginación ya era in-memory). user.role se guarda lowercased (create/patch/reassign).

### 5. ShareAccessModal (FE) — bug 'siempre operator'
- Diagnóstico validado CONTRA LA BD DEV (perfil AWS 'silia', tabla dev-app-silia-com-*): el POST del FE mandaba roleId=operator hardcodeado. 58 grants operator + 4 con otro rol → BE fiel, no bug BE.
- Fix: el grant DERIVA el rol del usuario seleccionado (su rol de org), mapeando nombre→roleId case-insensitive. Fallback a operator para teams y roles internos. Verificado en vivo: christopher (admin) → role_name 'admin'.

### 6. Fixes de review (commit 6aa248924)
- PR review (bug real): clearAbilityCache usaba key cruda; roleIdCache guardaba lowercased → roles con mayúsculas nunca se invalidaban. Fix: helper roleCacheKey() en los 3 sitios.
- Adversarial (BLOCK): listByAccount solo minusculizaba el input pero match exacto contra user.role guardado → usuarios mixed-case legacy desaparecían del filtro. Fix: match in-memory (ya hecho). Sin backfill necesario.
- LOW: comentario de RESERVED_ORG_ROLES aclarado (bypass superadmin).
