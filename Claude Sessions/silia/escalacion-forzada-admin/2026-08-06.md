- **Goal:** operador escala manualmente una conversación a Tickets y TOMA control, a cualquier hora.

## Estado: IMPLEMENTADO (backend), tests verdes, sin commitear.

## Hallazgos del análisis
- escalación == ticket (`EscalationRecord`). Hoy solo escala el LLM; no hay creación manual.
- El gate de horario vive SOLO en `EscalationEvaluatorService`; `createEscalation` NO valida horario → componer `createEscalation` + `assignToAgent`.
- `assignToAgent` exige `requires_takecontrol`; `handoffEscalation` exige `in_progress` + assignedTo==from → sirven para tomar control.
- La conversación guarda `hasActiveEscalation` + `activeEscalationId` (no `triggeredAt`) → cargar el existente con `findByConversation`.

## Decisiones (evolucionaron con el ticket)
1. ~~solo admin~~ → **permiso NUEVO `agent.inbox.force_escalate` para TODOS los roles del inbox**.
2. ~~sin asignar~~ → **AUTO-ASIGNA al operador (toma control, `in_progress`)**.
3. ~~409 si ya hay ticket~~ → **IDEMPOTENTE: toma control del existente** (assign si sin asignar, handoff si de otro, no-op si del mismo).
4. Bloquea la conversación (bot silenciado). Identidad del token. **+2 columnas** `isForced` + `forcedBy`/`forcedByName` (auditoría inmutable).
